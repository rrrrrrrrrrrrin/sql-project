1. GENERAL DESCRIPTION
------------------------------------------------------------

GameStore is a web application for browsing and publishing
video games.

The application uses a frontend-backend architecture.

Frontend: React + Vite
Backend: Python + FastAPI
Database: PostgreSQL
Database management: pgAdmin
Database communication: SQLAlchemy
Authentication: JWT (JSON Web Tokens)
Containerization: Docker + Docker Compose

------------------------------------------------------------

Technology:
- React
- JavaScript
- Vite
- CSS

Responsibilities:

- Display the game catalog.

4. BACKEND
------------------------------------------------------------

Technology:
- Python
- FastAPI
- SQLAlchemy
- Pydantic
- PyJWT
- PostgreSQL driver

Responsibilities:
- Process HTTP requests from the frontend.
- Validate incoming data.
- Register new accounts.
- Verify login credentials.
- Generate JWT tokens.
- Authenticate users.
- Check user roles and permissions.
- Retrieve games from PostgreSQL.
- Publish new games.
- Return JSON responses.

Main API endpoints:

GET  /                  - Backend status
GET  /api/health        - API health check
GET  /api/games         - Retrieve all games
POST /api/register      - Register an account
POST /api/login         - Log in
GET  /api/me            - Retrieve current account
POST /api/games         - Publish a game (publisher only)


5. AUTHENTICATION AND AUTHORIZATION
------------------------------------------------------------

Registration:
1. User enters username, email and password.
2. Frontend sends registration data to FastAPI.
3. Backend hashes the password using PostgreSQL pgcrypto.
4. Account is stored in PostgreSQL.
5. New accounts receive the "user" role.

Login:
1. User enters username and password.
2. Backend verifies credentials against password_hash.
3. Backend generates a JWT token.
4. Frontend receives and stores the token.
5. Token is sent in the Authorization header.

Authorization:
1. Backend extracts the JWT token.
2. Backend verifies the token signature and expiration.
3. Backend retrieves the account from PostgreSQL.
4. Backend checks the account role.
5. Only publishers can publish games.

Roles:
- user
- publisher

------------------------------------------------------------

Database management system:
PostgreSQL

Database name:
gamestore

Main tables:
- accounts
- games
- dlcs
- library
- game_reviews
- developers
- publishers
- game_developers
- game_publishers

Database responsibilities:
- Store user accounts.
- Store password hashes.
- Store user roles.
- Store game information.
- Store reviews and game libraries.
- Store developer and publisher information.

SQLAlchemy is used for database communication.
The current backend mainly uses SQLAlchemy Core and
parameterized SQL queries.

pgAdmin is used to inspect and manage the database.

10. SECURITY
------------------------------------------------------------

- Passwords are stored as hashes.
- JWT is used for authentication.
- JWT tokens have an expiration time.
- Backend verifies authentication.
- Backend checks publisher permissions.
- SQL queries use parameters.
- Database credentials are stored in .env.
- Database files are excluded from Git.
