Solution: 6) VERY IMPORTANT EDIT CONCERNING PORTS IN DOCKER COMPOSE!!!
I had an error that my password was wrong when i tried to run .\.venv\Scripts\python.exe -m uvicorn main:app --reload --host 127.0.0.1 --port 8080
command in backend folder. The problem wasn't the password tho.

[it could be as logging into the pgAdmin website uses account credentials (docker compose pgadmin service),
connecting pgAdmin to PostgreSQL uses a seperate database username and password (can match, listed in docker compose file under posgres service),
Python app connects directly to PostgreSQL at its localhost address (docker compose -> service postgres -> ports -"LOCALHOST ADDRESS":"5432")]

The problem was that there were 2 PostgreSQL servers and IPv4 goes to the wrong one

'''''''''''''''''''''''''''''''''''''''''''
Prove: in sql-project folder:
Where Docker thinks it published the port: docker port gamestore_db 
5432/tcp -> 0.0.0.0:5431
5432/tcp -> [::]:5431
This only says "Docker wants to listen on 5431." It does not prove Docker actually owns 5431.

The command that found the bug:
Get-NetTCPConnection -LocalPort 5431 -State Listen |
    Select-Object LocalAddress, LocalPort, OwningProcess |
    ForEach-Object {
        $p = Get-Process -Id $_.OwningProcess -ErrorAction SilentlyContinue
        [pscustomobject]@{
            Address = $_.LocalAddress
            Port    = $_.LocalPort
            PID     = $_.OwningProcess
            Process = $p.ProcessName
            Path    = $p.Path
        }
    } | Format-Table -AutoSize


Address Port   PID Process            Path
------- ----   --- -------            ----
::      5431 14980 com.docker.backend C:\Users\Lenovo\AppData\...\DockerDesktop\...
0.0.0.0 5431  7136 postgres           (native Windows PostgreSQL)

Port 5431 was claimed by two different processes on two different address families:
IPv6 (Address ::, process: com.docker.backend; docker container), IPv4 (Address: 0.0.0.0, process: postgres.exe; Native Windows PostgreSQL 18)

Inside the container, PostgreSQL still listens on 5432. Windows host (my Python, uvicorn, browser): localhost (address), 5433 (port)

Check 5433 is free first:
Get-NetTCPConnection -LocalPort 5433 -State Listen -ErrorAction SilentlyContinue
# no output = free
