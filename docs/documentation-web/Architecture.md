# Архитектура приложения GameStore

## 1. Общая информация

GameStore — веб-приложение для просмотра каталога
видеоигр и публикации новых игр.

Приложение реализовано с использованием клиент-серверной архитектуры.

Система состоит из трёх основных компонентов:

1. Frontend — пользовательский интерфейс.
2. Backend — обработка запросов и бизнес-логика.
3. Database — хранение данных.

Взаимодействие компонентов осуществляется по HTTP
с использованием API.

В качестве системы управления базами данных используется PostgreSQL.

## 4. Взаимодействие компонентов

Frontend взаимодействует с backend посредством Fetch API.

При получении каталога frontend отправляет GET-запрос
на endpoint /api/games.

Backend выполняет SQL-запрос к PostgreSQL,
получает записи из таблицы games и возвращает их
в формате JSON.

При публикации игры frontend отправляет POST-запрос
с информацией об игре и JWT-токеном.

Backend проверяет токен, определяет пользователя,
проверяет его роль и выполняет INSERT в таблицу games.

После успешной публикации frontend повторно загружает
каталог для отображения новой игры.

## 5. Архитектура базы данных

Для хранения информации используется PostgreSQL.

База данных GameStore содержит следующие основные таблицы:

- accounts — учётные записи пользователей;
- games — каталог видеоигр;
- dlcs — дополнения к играм;
- library — пользовательские игровые библиотеки;
- game_reviews — отзывы и оценки;
- developers — разработчики;
- publishers — издатели;
- game_developers — связь игр и разработчиков;
- game_publishers — связь игр и издателей.

Связи между таблицами реализованы с помощью
первичных и внешних ключей.

Для обеспечения целостности данных применяются
ограничения UNIQUE, NOT NULL и CHECK.

## 8. CI/CD и автоматизация

Для автоматизации сборки и проверки проекта
используется GitHub Actions.

При отправке изменений в репозиторий запускается CI workflow.

Frontend проходит установку зависимостей и сборку
с помощью Vite.

Backend проходит установку Python-зависимостей
и проверку синтаксиса.

В дальнейшем планируется расширить CI автоматическими
тестами и сборкой Docker-образов.

Развёртывание приложения будет выполняться
с использованием Docker Compose и deployment script.
