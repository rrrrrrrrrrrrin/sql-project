# Документация API GameStore

## 1. Обзор API

GameStore API — это программный интерфейс приложения GameStore,
разработанный с использованием Python и FastAPI.

API обеспечивает взаимодействие между frontend-приложением
на React и базой данных PostgreSQL через backend.

Основные задачи API:

- Регистрация новых пользователей.
- Аутентификация существующих пользователей.
- Получение информации о текущем аккаунте.
- Получение каталога игр.
- Публикация новых игр.
- Проверка пользовательских ролей и прав доступа.

API использует HTTP-запросы и JSON-формат для обмена данными.

Базовый адрес API в локальной среде разработки:

http://localhost:8080

Интерактивная документация доступна по адресу:

http://localhost:8080/docs


## 2. Архитектура и взаимодействие компонентов

Frontend взаимодействует с backend посредством HTTP-запросов.

Frontend разработан с использованием React и Vite.
Backend реализован на Python с использованием FastAPI.

Процесс взаимодействия:

1. Пользователь взаимодействует с пользовательским интерфейсом.
2. Frontend отправляет HTTP-запрос на backend с помощью Fetch API.
3. Backend получает и обрабатывает запрос.
4. Pydantic проверяет корректность входящих данных.
5. SQLAlchemy обеспечивает взаимодействие с PostgreSQL.
6. Backend формирует и возвращает ответ в формате JSON.
7. Frontend обрабатывает ответ и обновляет интерфейс.

Frontend не подключается непосредственно к PostgreSQL.
Все операции с базой данных выполняются через backend.


## 3. Аутентификация и авторизация

В GameStore используется механизм JWT (JSON Web Tokens)
для аутентификации пользователей.

### Регистрация

Новый пользователь может создать аккаунт, указав:

- Имя пользователя (username).
- Электронную почту (email).
- Пароль (password).

Перед сохранением в базе данных пароль хешируется
с использованием расширения PostgreSQL pgcrypto.

Все новые аккаунты получают роль "user".

### Вход в систему

Для входа пользователь указывает username и password.

Backend проверяет предоставленные учётные данные,
сравнивая пароль с сохранённым хешем.

При успешной аутентификации backend создаёт
подписанный JWT-токен.

Срок действия токена составляет 60 минут.

### Использование JWT

Для доступа к защищённым endpoint пользователь
должен передавать токен в HTTP-заголовке Authorization.

Формат:

Authorization: Bearer <access_token>

### Пользовательские роли

В приложении предусмотрены две роли:

- user — обычный пользователь;
- publisher — издатель игр.

Обычные пользователи могут просматривать каталог игр.

Издатели могут просматривать каталог и публиковать новые игры.

### Проверка прав доступа

Backend проверяет подпись и срок действия JWT-токена.

После проверки токена backend получает информацию
об аккаунте из PostgreSQL и проверяет его фактическую роль.

Frontend не предоставляет и не назначает права доступа.
Все ограничения на выполнение защищённых операций
контролируются backend.


## 4. Валидация данных

В GameStore используется несколько уровней проверки
корректности пользовательских данных.

### Валидация на frontend

React-формы используют встроенные возможности HTML
для проверки вводимых значений.

Применяются:

- Проверка обязательных полей.
- Проверка формата электронной почты.
- Проверка числовых значений.
- Проверка минимальных и максимальных значений
  для полей, в которых заданы соответствующие ограничения.
- Ограничение длины отдельных полей.

### Валидация на backend

Для проверки входящих данных используются Pydantic-модели.

Они проверяют типы данных, наличие обязательных полей
и дополнительные ограничения, определённые в моделях.

### Валидация на уровне базы данных

PostgreSQL обеспечивает соблюдение ограничений целостности:

- PRIMARY KEY;
- FOREIGN KEY;
- UNIQUE;
- NOT NULL;
- CHECK.

Некорректные данные отклоняются до завершения
соответствующей операции с базой данных.


## 5. HTTP-коды ответов и обработка ошибок

API использует стандартные HTTP-коды для обозначения
результатов выполнения запросов.

Основные используемые коды:

- 200 OK — получение каталога, проверка аккаунта, health check (запрос успешно выполнен).
- 201 Created — регистрация пользователя и публикация игры (ресурс успешно создан).
- 400 Bad Request — ошибка регистрации или публикации (ограничение БД), например дублирование уникального значения.
- 401 Unauthorized — неправильные данные входа, отсутствие или недействительность JWT (аутентификации).
- 403 Forbidden — попытка зарегистрироваться с ролью publisher или публикация обычным пользователем 
  (недостаточно прав для выполнения операции).
- 422 Unprocessable Entity — входящие данные не прошли проверку.
- 503 Service Unavailable — сервис или база данных недоступны.

Сообщения об ошибках возвращаются в формате JSON.

Пример:

{
    "detail": "Incorrect username or password."
}

Поле detail содержит описание возникшей ошибки.


## 6. Правила формирования запросов

В GameStore используются следующие форматы HTTP-запросов.

### JSON

Формат JSON применяется для отправки структурированных данных,
например при регистрации пользователя и публикации игры.

Заголовок:

Content-Type: application/json

### Form URL Encoded

Для входа в систему используется формат
application/x-www-form-urlencoded.

Он применяется в соответствии с OAuth2 password flow,
реализованным в backend.

Заголовок:

Content-Type: application/x-www-form-urlencoded

### Заголовок авторизации

Для доступа к защищённым endpoint используется JWT-токен.

Формат:

Authorization: Bearer <access_token>

### Формат ответов

API возвращает данные в формате JSON.

Даты передаются в формате:

YYYY-MM-DD

Стоимость игр возвращается в числовом формате.


## 7. Спецификация API и интерактивная документация

API GameStore использует REST-подобную организацию
HTTP-endpoint.

Полная спецификация API автоматически генерируется
FastAPI в формате OpenAPI.

Доступны следующие инструменты документации:

- Swagger UI: localhost:8080/docs
- ReDoc: localhost:8080/redoc
- OpenAPI JSON: localhost:8080/openapi.json

Swagger UI предоставляет подробную информацию:

- Доступные endpoint.
- Используемые HTTP-методы.
- Параметры запросов.
- Модели тела запросов.
- Модели ответов.
- Требования к аутентификации.
- Возможные HTTP-коды ответов.

OpenAPI JSON представляет собой машиночитаемую
спецификацию программного интерфейса.

Она может использоваться внешними инструментами
для тестирования и интеграции с API.

### Основные endpoints API

- **GET `/`** — проверка доступности backend.
- **GET `/api/health`** — проверка состояния API.
- **GET `/api/games`** — получение списка всех игр.
- **POST `/api/register`** — регистрация нового пользователя.
- **POST `/api/login`** — вход пользователя и получение JWT-токена.
- **GET `/api/me`** — получение информации о текущем авторизованном пользователе. Требуется Bearer-токен.
- **POST `/api/games`** — публикация новой игры. Требуется авторизация с ролью `publisher`.

Подробное описание каждой endpoint, включая параметры,
модели запросов и ответов, доступно в Swagger UI.
